01누가 쓰나

경쟁 제품 리뷰를 읽고 우리 제품 기획에 반영해야 하는 스피겐 이커머스·기획 담당자. 상품마다 리뷰 수십 개를 훑어 "뭐가 좋다는 거고 뭐가 불만인가"를 매번 손으로 정리한다.

02지금은

아마존 리뷰 페이지를 스크롤하며 눈으로 읽고 메모. 상품 하나에 10~15분, 정리 기준이 사람마다 달라 비교가 안 된다.

03없앨 동작 하나

리뷰를 읽고 요약을 손으로 쓰는 것 — 붙여넣기 한 번으로 같은 틀(긍정 2·페인 2·총평 1)의 5줄이 나온다.

04핵심 기능 1개

리뷰 10개를 붙여넣고 「분석」을 누르면 Vercel 함수가 Anthropic SDK로 Claude(Sonnet 5)를 구조화 출력으로 호출하고, {긍정 요인, 페인포인트, 총평} JSON이 5줄로 렌더된다. 호출마다 토큰·비용과 "1천 건이면 $__"가 찍히고, 결과와 usage는 원장(s06_analyses)에 쌓인다. 개발자도구 네트워크 탭에 API 키가 없다.

05안 만드는 것 3개

  • 리뷰 페이지 크롤링 — /product-reviews/·페이지네이션·로그인 없음. 스파이크에서 /dp/ 원본에 리뷰가 0개임을 확인해 「보드에서 가져오기」도 안 만든다
  • 스트리밍·채팅 UI — 단발 요청/응답. 5줄 JSON에 스트리밍은 필요 없다
  • 분석 이력의 사용자별 격리 — 공용 원장 1테이블(읽기 공개, 쓰기 service key). 로그인·RLS는 S05에서 했다

06성공 판정

  • 리뷰 10개 붙여넣기 → 5줄이 JSON 스키마를 거쳐 뜬다 (긍정 ≤2·페인 ≤2·총평 1 — 스키마가 5줄을 강제)
  • 호출마다 입력/출력 토큰·비용·"1천 건이면 $__"가 실측으로 찍힌다 (usage 기반, 추정 아님)
  • 개발자도구 네트워크 탭에 /api/analyze 외 외부 호출이 없고 키가 보이지 않는다

07내 옵션 + 이유

넷 다 같은 Claude라 "어디서 부르느냐"만 다르다. Anthropic SDK 직접이 가장 직접적이고, SDK의 구조화 출력(output_config.format + zod)이 "JSON을 거쳐"라는 이번 주 제약을 그대로 충족하며, 응답 usage로 건당 비용이 바로 나온다. Vercel AI SDK는 스트리밍·타입 검증을 대신 해주지만 5줄 단발 응답엔 레이어가 하나 더일 뿐이고, Bedrock은 AWS 계정·IAM 셋업이 스파이크를 잡아먹는다. 모델은 Opus 5와 Sonnet 5를 같은 입력으로 실측해 결과가 동등하고 시간 절반·비용 1/3인 Sonnet 5로 고정했다.

08리스크 + 검증법

걱정되는 것: ① 구조화 출력이 스키마를 정말 강제하나(5줄 넘치거나 깨진 JSON) ② /dp/ 원본에 리뷰가 있어서 보드 연결이 되나 ③ 키가 브라우저로 새는 경로
화요일 스파이크로 확인: ① parse + zod로 첫 호출에 정확히 5줄·end_turn, Opus/Sonnet 둘 다 (1천 건 $15 vs $5) ② 1MB 진짜 페이지에 리뷰 마커 0개 — 하이드레이션 이후에만 존재, 붙여넣기로 확정 ③ 키는 Vercel env에만, 브라우저는 /api/analyze만 호출 — 네트워크 탭 실측. 상세 06/SPIKE.md
