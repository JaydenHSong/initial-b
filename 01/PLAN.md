## 누가 쓰나

iBD 팀원 3~5명. **금요일 오후 데모데이에 프로젝터로 다 같이 띄워놓고** 발표 순서대로 연다. 시즌 18주 내내 매주 같은 화면을 본다. 제출도 이 화면에서 한다.

## 지금은

없다. 시즌 첫 주라 대체할 이전 방식 자체가 없다. 데모데이가 끝나면 그날 본 링크가 어디에도 안 남는다.

## 없앨 동작 하나

**제출이라는 동작 자체.** 원래 규약은 report.html 복사 버튼 → 시트에 붙여넣기인데, 이걸 "배포 URL 하나 드랍"으로 줄인다. 나머지 정보는 사이트가 알아서 채운다.

## 핵심 기능 1개

**배포 URL을 드랍하면, 그 사이트의 기획서(`URL/docs/plan.html`)를 읽어 카드로 저장된다.**

폴더 규약 덕에 모든 제출 사이트는 기획서가 같은 자리에 있다. 드랍하는 순간 서버 함수가 그 기획서를 한 번 읽어 제목·만든 사람·스프린트·스택 옵션을 뽑아 DB에 저장하고, 갤러리는 DB를 읽어 카드를 그린다.

```
[URL 입력창] ──드랍──▶ 서버 함수: URL/docs/plan.html fetch → data-f 파싱 → DB에 행 저장
                                                                      │
        팀원 아무나 갤러리를 열면 ◀── DB 읽어 카드 그리드 렌더 ◀─────────┘
```

- 브라우저에서 남의 사이트를 직접 읽으면 CORS에 막힌다 → **읽기는 서버 함수가 드랍 시점에 1회.** 이후엔 DB만 읽으므로 빠르다.
- 기획서를 못 읽는 사이트(404, 규약 미준수)는 **URL과 도메인만으로 저장하고 카드에 "기획서 없음" 표시.** 드랍이 실패하는 일은 없다.

## 화면 — 한 장이 전부다

```
┌─────────────────────────────────────────────┐
│  iBD 바이브 코딩 · Season 1    [URL 드랍 ___]│
├─────────────────────────────────────────────┤
│  S01                                        │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐        │
│  │ 제목     │ │ 제목     │ │ 제목     │  ← 카드 │
│  │ 만든 사람 │ │ 만든 사람 │ │ 만든 사람 │        │
│  │ 스택 옵션 │ │ 스택 옵션 │ │ 스택 옵션 │        │
│  │ 한 줄 소개│ │ 한 줄 소개│ │ 한 줄 소개│        │
│  │ 기획서·리포트 ↗           │               │
│  └─────────┘ └─────────┘ └─────────┘        │
│  S02 (다음 주부터 위에 쌓임)                   │
└─────────────────────────────────────────────┘
```

- 스프린트별 묶음, **최신 스프린트가 맨 위** — 데모데이에 열면 이번 주 것이 스크롤 없이 보인다. 같은 스프린트 안은 드랍된 순서.
- 카드 = 제목(크게) · 만든 사람 · 스택 옵션 배지 · 한 줄 소개. 프로젝터에서 읽히는 건 제목과 배지 — 이 둘을 키운다.
- 카드 클릭 → 그 사이트 새 탭. 카드 아래 작은 링크: 기획서 · 리포트 (`URL + /docs/…`로 조립).
- 상태 3개: 로딩 한 줄 / DB 못 읽으면 에러 한 줄 / 0개면 "아직 제출이 없다" 한 줄.
- 드랍 입력창은 헤더 오른쪽 한 칸. URL 붙여넣고 엔터가 전부다.
- 모바일은 카드 1열 낙하만. 헤더에 총 카드 수 하나만 표시.

## 안 만드는 것 3개 — 절대 만들지 마라

1. **스택별 필터** — 갤러리 v2 과제
2. **검색** — 100장 남짓, 스크롤로 충분
3. **수정·삭제 UI** — 잘못 드랍하면 DB에서 지운다 (관리자 = 만든 사람). 로그인 없는 사이트에 삭제 버튼을 두면 장난에 무방비다

## 성공 판정

- [ ] 배포된 URL이 있고 남이 열어서 쓸 수 있다
- [ ] URL 하나를 드랍하면 **다른 사람 브라우저에서도** 새로고침으로 카드가 보인다
- [ ] 규약을 지킨 사이트는 제목·만든 사람이 **자동으로** 채워진다
- [ ] 규약을 안 지킨 URL도 도메인 카드로 저장된다 (드랍 실패 없음)
- [ ] 카드 클릭 → 사이트, 작은 링크 → 기획서/리포트
- [ ] 프로젝터 거리에서 제목이 읽힌다 · 모바일 안 깨짐
- [ ] DB 접근 키가 브라우저에 노출되지 않는다 (쓰기는 서버 함수 뒤)
- [ ] 배포에 걸린 분 · 첫 로딩 초를 숫자로 말할 수 있다

## 왜 시트 규약에서 이탈했나 — 금요일 설명용

- 가이드의 제출 인프라 목표는 "제출이 30초 안에 끝나야 한다"다. URL 드랍은 그걸 5초로 줄이고, 복붙 단계(report.html 버튼 → 시트)를 없앤다.
- 폴더 규약(`/docs/plan.html` 고정 경로)이 이미 기계가 읽을 수 있는 데이터 소스다. 시트에 같은 정보를 사람 손으로 한 번 더 적는 건 중복 입력이다.
- **스택 비교표 탭은 시트에 그대로 남는다.** 이탈하는 건 레지스트리 탭 하나다.
- 대가: DB를 한 주 일찍 만진다. 채택 안 되면 팀은 시트 방식 갤러리를 쓰면 되고, 이 사이트는 첫 등록 항목이 된다.

## 제약

- 로그인 없이 동작 (읽기·드랍 모두)
- 데이터 하드코딩 금지 — 카드가 DB에서 나와야 한다
- DB service key가 브라우저에 노출되면 미완
- 배포 후 `사이트URL/docs/plan.html`이 열려야 한다 (이 사이트 자신도 규약을 지킨다 — 자기 URL을 자기한테 드랍하면 카드가 생겨야 한다)
