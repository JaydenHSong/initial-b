**안 만드는 것 3개 — 절대 만들지 마라**

1. **가격 자동 추적 · 알림** — 매일 수집하는 크론은 **S09**, 알림 채널은 **S12**의 스택 카드다. 당겨 쓰면 그 주에 배울 게 없어지고, 이번 주 구현 시간이 태그 스키마가 아니라 크론 디버깅에 간다. 등록 시점 1회 수집이면 충분하다
2. **수정·삭제 UI** — 잘못 넣으면 Firestore 콘솔에서 지운다. 로그인 없는 사이트에 삭제 버튼을 두지 않는다
3. **텍스트 검색·정렬** — 검색을 붙이는 순간 태그가 필요 없어지고 이번 주 주제가 사라진다

**제약**
- **로그인 없이 동작. 인증에 시간 쓰지 마라** (인증은 S03 스택 카드다)
- **데이터 하드코딩 금지** — 저장한 제품이 「내 옵션」 저장소에서 나와야 한다
- 배포 후 `사이트URL/docs/plan.html`이 열려야 한다 (갤러리 셀프 드랍으로 검증)
- **태그는 다대다다.** 이걸 어떻게 표현했는지가 이번 주 비교의 핵심 — 스키마 설계를 리포트에 적을 수 있어야 한다

**이번 주 작업 폴더:** `02/` · 다음 주부터 `03/`, `04/`로 늘린다. **한 레포 안에서 주차 폴더로 분리하고, 폴더마다 독립 Vercel 프로젝트를 붙인다.** 팀 문서 템플릿은 이 레포 **`_template/public/docs/`** (plan.html · report.html — data-f 규약).

호스팅은 **Vercel `initial-b02`** (Root Directory `02`, git 연결 — main에 푸시하면 자동 배포). 프로젝트 개명 시 도메인이 재생성되므로 이름은 처음에 확정할 것.

**주차 폴더마다 빌드 경로 필터를 반드시 건다.** 안 걸면 어느 파일을 고쳐도 연결된 프로젝트가 전부 재빌드된다. 방법이 둘인데 **Vercel 설정 쪽만 써라**:
- Settings → Git → **Skip deployments**(루트 디렉터리에 변경이 없으면 건너뜀) — 푸시에 담긴 커밋 전체를 본다. 이쪽이 정답이다.
- `vercel.json`의 `ignoreCommand`(`git diff --quiet HEAD^ HEAD ./`) — **쓰지 마라.** 커밋 하나만 비교하므로 두 가지로 오판한다. ①여러 커밋을 한 번에 푸시하며 앞 커밋에서만 그 폴더를 고쳤을 때. ②머지 커밋일 때 — `HEAD^`가 첫 부모(머지를 실행한 브랜치 쪽)라, 그 브랜치에 이미 해당 폴더 변경이 들어 있었다면 "변경 없음"으로 읽혀 빌드가 Canceled 된다. 2026-08-07 `02/`에서 실제로 ②가 터져 initial-b02가 빈 배포를 프로덕션 별칭에 쥔 채 전 경로 404가 됐다.

## 01/ = 팀 공식 갤러리 (S01 결과물 — 계속 살아 있다)

https://initialb.vercel.app · Vercel `initial-b01`(Root Directory `01`, git 연결 — **main에 푸시하면 자동 배포**) · DB는 Supabase iBD Coliseum `sites` 테이블, 쓰기는 `SUPABASE_SERVICE_KEY`를 쓰는 `01/api/drop.js`만.

- 매주 제출(드랍)을 받는 살아 있는 인프라다. **스프린트 기간에도 계속 떠 있어야 한다** — 반쯤 만든 상태로 두지 마라.
- 「안 만드는 것 3개」는 S01 스프린트 판정 기준이었고 제출로 종료됐다. 이제 갤러리 개선은 **별도 작업**으로 다룬다.
- `01/` 밖 변경에 재빌드되지 않게 하는 필터는 **Vercel Settings → Git → Skip deployments 토글**로 건다. `01/vercel.json`에는 `ignoreCommand`를 두지 않는다 — 머지 커밋에서 오판해 조용히 빌드를 건너뛴다(위 「빌드 경로 필터」 항목). 갤러리는 매주 제출을 받는 인프라라, 재배포가 조용히 실패하면 제출 화면이 옛 버전으로 남는다.
- 매주 「이번 주」 칸을 갈면 두 사본을 같이 갱신한다. **git에 올라가는 `01/docs/CLAUDE.md`가 원본**이고 루트 `CLAUDE.md`는 gitignore된 로컬 사본이다: `cp 01/docs/CLAUDE.md CLAUDE.md`

**레포 하나에 18주를 담는 구조 — 배포 시 주의**
- 호스트별 GitHub 연동은 서로 독립이다. 한 레포를 Vercel·Cloudflare·Netlify에 동시에 붙여도 충돌하지 않는다. 주차마다 다른 호스트를 써도 된다.
- **레포당 프로젝트 수 상한이 호스트별로 따로 있다** — Cloudflare Pages 5개, Vercel Hobby 25개. 한 호스트에 18주를 몰면 Cloudflare는 6주차에 막힌다. 나눠 쓰면 안 걸린다.
- **빌드 경로 필터를 반드시 건다.** 안 걸면 어느 파일을 고치든 연결된 프로젝트 전부가 재빌드된다. Cloudflare는 Settings → Build → Build watch paths, Vercel은 Settings → Git → **Skip deployments** 토글. `git diff HEAD^ HEAD` 류의 ignore 명령은 쓰지 마라 — 머지 커밋과 다중 커밋 푸시에서 오판한다.
- 호스트별 설정 파일(`vercel.json`, `netlify.toml`, `wrangler.toml`)은 각 주차 폴더 안에 둔다.

## 이 프로젝트가 뭔지

주 1회 사이클로 도는 **훈련용 MVP**다. 제품이 아니다. 금요일 오전에 배포된 상태로 3분 시연하는 것이 전부이고, 다음 주에는 다른 프로젝트를 시작한다.

목표는 **기획력 · 스택 판단력 · 순발력**이지 코드 품질이 아니다. 유지보수는 고려하지 않는다.

## 폴더 규약 — 이대로 만든다

갤러리는 **사이트 URL 하나만** 받는다. 문서 위치는 규약으로 유도되므로 경로를 바꾸지 마라.

```
my-project/
├─ CLAUDE.md
├─ SPIKE.md                   ← 화요일 스파이크 기록
└─ public/                    ← 정적 파일 루트 (Astro·SvelteKit이면 static/)
   └─ docs/
      ├─ plan.html            ← 1페이지 기획서   (배포와 함께 공개)
      └─ report.html          ← 스택 리포트      (목 18:00 제출)
```

배포하면 `사이트URL/docs/plan.html`, `사이트URL/docs/report.html`로 열려야 한다.
**두 파일은 팀 템플릿(`_template/public/docs/`)을 복사해서 쓴다.** 새로 만들지 마라.

- 템플릿의 **레이아웃과 CSS를 건드리지 마라.** 18주 내내 같은 모양이어야 비교가 된다.
- **`data-f="..."` 속성을 지우지 마라.** 드랍하면 갤러리가 이 속성으로 plan.html·report.html을 읽어 카드와 스택 비교표를 채운다. 지우면 그 칸이 빈다.
- 채울 것은 `data-f`가 붙은 요소의 **안쪽 텍스트뿐**이다. 안 채운 칸은 지우지 말고 `기록 없음`이라고 써라.
- `data-f="url"`의 `href`는 **배포된 사이트 주소**로 바꾼다. 기본값 `../`을 그대로 두면 레지스트리에 상대경로가 들어간다.

## 절대 규칙 (어기면 그 주가 망한다)

### 1. 기능은 하나다
위에 적은 **핵심 기능 1개**만 만든다. 그것이 입력 → 처리 → 결과까지 끊김 없이 도는 게 유일한 성공 조건이다.

**요청하지 않은 기능을 추가하지 마라.** 좋은 아이디어가 떠올라도 코드로 만들지 말고 **한 줄로 제안만** 하고 넘어가라.

특히 이런 걸 알아서 붙이지 마라:
`로그인/회원가입` `관리자 페이지` `다크모드 토글` `다국어` `설정 화면` `온보딩 투어` `애니메이션` `검색` `필터` `페이지네이션` `테스트 프레임워크` `CI 설정` `Docker` `에러 바운더리` `로딩 스켈레톤`

위 목록 중 **이번 주 스택 카드에 해당하는 것만** 예외다. (예: 스택 카드가 "인증"이면 로그인은 만든다)

### 2. 스택은 지정된 것만 쓴다
「내 옵션」에 적힌 스택을 **실제 동작 경로에** 쓴다. 이번 주 훈련의 목적이 그 스택을 직접 만져보는 것이다.

- 더 쉬운 대안이 있어도 **갈아타지 마라.** 그게 이번 주 배울 것이다.
- "이건 X로 하면 더 간단합니다" → 말은 해도 되지만 **코드는 지정된 스택으로** 쓴다.
- **데이터를 하드코딩하지 마라.** 스택을 안 쓴 것과 같고, 그 주는 미완 처리된다.
- **LLM은 Claude로 고정이다.** 다른 모델로 바꾸자고 제안하지 마라. (예외: 임베딩. Claude에는 임베딩 API가 없어서 S13에서는 Voyage AI를 쓴다)

### 3. 파일은 최소로
- 기본은 **단일 파일**. 정말 필요할 때만 나눈다.
- 폴더 구조를 미리 잡지 마라. `components/`, `utils/`, `types/`, `hooks/` 를 선제적으로 만들지 않는다.
- 추상화하지 마라. 두 번 반복되는 코드는 그냥 두 번 쓴다. 세 번째에 고민한다.

### 4. 항상 배포 가능한 상태
- 매 작업 단위가 끝나면 **로컬에서 실제로 떠야 한다.**
- 반쯤 만든 기능을 커밋해두고 다음으로 넘어가지 마라.
- 큰 리팩터링을 제안하지 마라. 이번 주 안에 안 끝난다.

### 5. 막히면 3번 만에 멈춘다
같은 에러를 **세 번 고쳐도 안 되면 멈추고 보고**하라. 우회로를 계속 파지 마라.

```
막힌 지점: ___
시도한 것 3가지: ___
내 추측: ___
선택지: (A) 이렇게 우회 (B) 스택 옵션 교체 (C) 기능 범위 축소
```

판단은 내가 한다. **이 기록은 목요일 스택 리포트에 그대로 들어간다.**

### 6. 보안 최소선
- **API 키를 클라이언트 코드에 두지 마라.** 서버 함수나 환경변수 뒤에 둔다.
- `.env`를 커밋하지 마라.
- 이 둘만 지킨다. 나머지 보안 강화는 이번 주 범위가 아니다.

## 요일별 모드

작업을 시작할 때 내가 요일을 말한다. 모드에 맞춰 행동하라.

### 월요일 — 기획 모드
**코드를 쓰지 마라.** 질문을 던져 범위를 좁히는 것만 한다.
- 아이디어를 듣고 **질문 3개**로 좁힌 뒤, 「핵심 기능 1개」와 「안 만드는 것 3개」를 제안한다.
- 기능을 늘리는 방향의 제안은 하지 마라. 줄이는 방향만.

### 화요일 — 스파이크 모드
**목적은 만드는 게 아니라 "이 스택이 되는지" 알아내는 것.**
- UI 없음. 디자인 없음. 예외 처리 없음.
- **버릴 코드다.** 재사용 가능하게 짜지 마라. 가장 짧게 써라.
- 성공 판정은 **됐다 / 안 됐다** 둘뿐. 되는 순간 멈춰라.
- 끝나면 `SPIKE.md`에 기록: 셋업에 걸린 시간(분) / 막힌 지점 1개 / 문서 품질(상중하) / 무료 한도

### 수 · 목요일 — 구현 모드
- 핵심 기능 1개의 **happy path 먼저.** 정상 흐름이 끝까지 돌고 난 뒤에 예외를 본다.
- **목요일에는 새 기능을 시작하지 마라.** 배포와 첫 화면 정리만.

### 목요일 마지막 — 제출 모드

내가 "제출물 만들어줘"라고 하면 아래 셋을 한다. **추측으로 채우지 말고 모르면 `기록 없음`이라고 써라.**

**① `public/docs/report.html` 채우기** — 이번 주 대화와 `SPIKE.md`가 근거다. `data-f` 요소의 텍스트만 바꾼다.

| 필드 | 규칙 |
|---|---|
| `minutes` | **숫자만.** 셋업부터 첫 데이터가 저장(또는 수집)되기까지 걸린 분 |
| `blocker` | 가장 시간을 뺏은 지점 **하나만.** 여러 개 쓰지 마라 |
| `docs` · `ai` | `상` / `중` / `하` 중 하나 |
| `fit` | `잘 맞음` / `보통` / `안 맞음` 중 하나 |
| `conclusion` | "____ 같은 경우에는 이걸 쓰겠다 / 안 쓰겠다" 형태 |
| `url` | `href`를 배포된 사이트 주소로 |

**② `public/docs/plan.html` 최종 확인** — 만든 것과 기획서가 어긋나면 기획서를 고쳐서 맞춘다. 특히 「안 만드는 것 3개」가 실제로 안 만들어졌는지.

**③ 데모 3분 시연 순서** — 클릭 순서만 5줄 이내. 설명 문구는 쓰지 마라.

> **비교표는 시트가 아니라 갤러리에 쌓인다.** 드랍하면 갤러리가 report.html의 `data-f`를 읽어 https://initialb.vercel.app/compare.html 에 한 줄을 만든다. 네가 TSV를 출력할 필요는 없다 — report.html을 정확히 채우는 것이 네 일이다. **리포트를 나중에 고쳤으면 같은 URL을 다시 드랍해야 표가 갱신된다.**

## S01 — 팀 갤러리 (1주차만 해당)

1주차 결과물이 시즌 인프라가 된다. 다른 주와 다른 점:

- 가이드의 허용 조항("레지스트리 도구는 바꿔도 된다")에 따라 **레지스트리를 시트 → Supabase DB로 교체**했다. 제출 = 갤러리에 배포 URL 드랍(5초). **「스택 비교표」도 시즌 중 DB로 옮겼다** — 드랍 시 report.html을 함께 읽어 `/compare.html`에 쌓인다. 시트는 더 쓰지 않고, report.html의 복사 버튼도 뺐다.
- 드랍하면 서버 함수가 그 사이트의 `/docs/plan.html`을 읽어 카드 메타(제목·만든 사람·스택·소개·소스)를 자동으로 채우고 스크린샷을 1회 찍는다. 규약 미준수 URL은 도메인 카드로 폴백 — 드랍 실패는 없다.
- 레지스트리(DB)에 행이 늘고 새로고침에 카드가 늘어나면 성공 — S01 판정 그대로 통과.
- 데모데이에서 하나를 팀 공식 갤러리로 채택한다.
- 문서 링크는 `URL + /docs/plan.html`, `URL + /docs/report.html`로 **직접 조립**한다. 링크 열은 어디에도 없다.

## 통합 주 (S05 · S09 · S13 · S17)

이 네 주는 전원 같은 스택으로 **깊게** 파는 주다. 위 규칙 중 다음이 달라진다.

- **최소로 하지 마라.** 그 스택의 지정된 기능을 반드시 써라.
  - **S05** Postgres — 테이블 3개 + JOIN 1회 + RLS 정책 1개
  - **S09** 서버리스 + 크론 — 자동 실행 로그 2회 이상
  - **S13** pgvector RAG — 출처 표시 필수. 임베딩은 Voyage AI, 답변 생성만 Claude
  - **S17** 같은 기능을 Postgres와 Firebase **양쪽으로 두 벌.** 그래서 기능은 극단적으로 작아야 한다 (화면 1개, 기능 1개)
- 지정 기능을 우회하는 더 쉬운 방법을 제안하지 마라. 그걸 쓰는 게 목적이다.
