01누가 쓰나

iBD 팀원 3~5명. 금요일 오후 데모데이에 프로젝터로 다 같이 띄워놓고 발표 순서대로 연다. 시즌 18주 내내 매주 같은 화면을 본다. 제출도 이 화면에서 한다.

02지금은

없다. 시즌 첫 주라 대체할 이전 방식 자체가 없다. 데모데이가 끝나면 그날 본 링크가 어디에도 안 남는다.

03없앨 동작 하나

제출이라는 동작 자체. 원래 규약(report 복사 → 시트 붙여넣기)을 "배포 URL 드랍 5초"로 줄인다. 나머지 정보는 사이트가 알아서 채운다.

04핵심 기능 1개

배포 URL을 드랍하면 그 사이트의 기획서(/docs/plan.html)를 읽어 카드로 저장된다. 폴더 규약이 곧 데이터 소스다. 드랍 순간 스크린샷도 1회 찍어 카드 썸네일로 저장한다. 기획서가 없는 URL도 도메인 카드로 저장된다 — 드랍 실패는 없다.

05안 만드는 것 3개

  • 스택별 필터 심화 — 갤러리에 칩 필터 하나만. 그 이상(복합 조건·정렬 옵션)은 v2
  • 검색 — 시즌이 다 차도 100장 남짓, 스크롤과 스프린트 점프로 충분
  • 수정·삭제 UI — 로그인 없는 사이트에 삭제 버튼은 무방비. 잘못 드랍하면 관리자가 DB에서 지운다

06성공 판정

  • URL 하나를 드랍하면 다른 사람 브라우저에서도 새로고침으로 카드가 보인다
  • 규약을 지킨 사이트는 제목·만든 사람·스택·소개·소스가 자동으로 채워진다
  • 규약을 안 지킨 URL도 도메인 카드로 저장된다 (드랍 실패 없음)
  • 카드 클릭 → 사이트, 작은 링크 → 기획서·리포트·소스
  • 프로젝터 거리에서 제목이 읽히고, 모바일에서 안 깨진다

07내 옵션 + 이유

Vercel — 드랍 시 남의 사이트 기획서를 읽어야 해서 서버 함수가 필요하고(브라우저는 CORS에 막힘), 주 1회 열리는 화면이라 콜드스타트 없는 호스트여야 한다(Render 탈락). 레지스트리는 가이드의 허용 조항("레지스트리 도구는 바꿔도 된다")에 따라 시트 → DB(Supabase)로 교체 — 자동으로 읽을 수 있고 제출이 5초로 끝난다.

08리스크 + 검증법

걱정했던 것: 서버 함수의 외부 fetch, DB 연결, 키 노출 — 화요일 스파이크로 전부 "됐다" 판정.
남은 리스크: 팀 템플릿의 data-f 필드 확정 전까지는 <title> 폴백으로 파싱. 템플릿 초안은 _template/public/docs/에 있다.
