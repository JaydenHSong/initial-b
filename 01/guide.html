화요일

스택 스파이크는
버릴 코드입니다.

앱을 만드는 게 아닙니다. UI 없고, 디자인 없고, 기능 없습니다. 판정은 됐다 / 안 됐다 둘뿐입니다.

내가 고른 스택화요일에 하는 것 — 이게 전부
Firestore빈 페이지에 버튼 1개 → 누르면 레코드 1개 저장 → 새로고침해도 남아있나
Playwright상품 페이지 1개에서 가격 문자열 하나를 콘솔에 찍기 — 차단되는지 여기서 알게 된다
Supabase Auth구글 로그인 눌러서 내 이메일이 화면에 뜨나
Resend내 메일함에 "test" 한 줄 도착시키기
pgvector문장 3개 넣고 유사한 것 1개 꺼내기
목적은 만드는 게 아니라 알아내는 것이다. 바이브 코딩의 가장 흔한 실패는 목요일 밤에 "어, 크롤링이 차단되네" "이 인증은 도메인 검증이 필요하네"를 발견하는 것이다. 그 시점엔 손쓸 방법이 없다. 화요일에 알면 옵션을 바꿀 시간이 이틀 남는다.

스파이크 코드는 본 프로젝트에 안 써도 된다. 버리는 게 정상이다.

데모 전에 본인이 체크합니다.

  • URL이 있다. 남이 링크를 열어 쓸 수 있다. 로컬만 도는 건 미완
  • 핵심 기능 1개가 입력에서 결과까지 끊김 없이 돈다
  • 내가 고른 스택이 실제 동작 경로에 있다. 흉내가 아니라
  • 첫 화면에서 5초 안에 뭐 하는 사이트인지 이해된다
  • 모바일에서 레이아웃이 안 깨진다. 예쁠 필요는 없다
  • 기획서와 스택 리포트가 있고 만든 것과 일치한다
  • 3분 안에 시연 가능하다
  • 안 만든 것 3개를 말할 수 있다

이건 MVP가 아닙니다

  • 로그인과 관리자 페이지는 있는데 정작 핵심 기능이 미완
  • 화면은 예쁜데 버튼을 눌러도 아무 일도 안 일어난다
  • 기능이 5개인데 다 반쯤만 된다
  • 데이터가 전부 하드코딩되어 있다 — 스택을 안 쓴 것
  • 나 자신도 이번 주에 한 번도 안 써봤다
  • 시연 중 "이건 아직 안 돼요"가 두 번 이상 나온다
매주 셋 중 하나를 포기해야 한다 — 기능 개수 · 완성도 · 사용자 범위.
우리는 항상 기능 개수를 포기한다. 기능 1개를 끝까지 되게 만드는 쪽을 선택한다.

CLAUDE.md

만들지 않게.

바이브 코딩의 가장 흔한 실패입니다. 기능 1개만 만들자고 했는데 로그인과 다크모드, 관리자 페이지가 딸려옵니다.

S01 · 갤러리를 만든다

각자 다른 호스팅으로 갤러리를 만든다. 이 주의 제출물은 갤러리 자체다. 데모데이에서 하나를 팀 공식으로 채택하고, 만든 사람이 관리자가 된다. 채택 안 된 것들은 버리지 않고 갤러리의 첫 등록 항목이 된다.

폴더 규약 — 문서는 늘 같은 자리에

갤러리는 사이트 URL 하나만 받는다. 기획서와 스택 리포트는 정해진 경로에 두고, 갤러리가 URL + /docs/plan.html로 링크를 조립한다. 그래서 레지스트리에 링크 열이 없다.
