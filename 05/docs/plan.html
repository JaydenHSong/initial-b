01누가 쓰나

경쟁 제품 가격을 챙기는 스피겐 이커머스 담당자들 — 이번 주부터는 각자 계정으로. S04 보드는 전 세계 공용 1개라 실제로 모르는 상품이 남의 손에 드랍돼 섞였다.

02지금은

S04 수집기는 "지금 가격"만 안다. 지난주 가격은 스크린샷이나 기억에 의존하고, 보드는 공용이라 팀원끼리 데이터가 섞인다.

03없앨 동작 하나

가격이 변했는지 확인하려고 지난 기록을 사람이 뒤지는 것 — 관측이 DB에 이력으로 쌓이고 Δ가 계산돼 나온다.

04핵심 기능 1개

Google 로그인하면 내 워크스페이스 보드가 열리고, URL 드랍 → 즉시 등록 → 백그라운드 수집이 채우되 관측마다 이력이 쌓인다. 표에 전회 대비 Δ, 행을 누르면 관측 이력 전체. 남의 워크스페이스는 RLS가 차단한다.

05안 만드는 것 3개

  • 크론 정기 수집 — S09 카드. 관측점은 드랍/재드랍 시점에만 쌓인다
  • 목표가 알림 — S12 카드
  • 워크스페이스 초대·멤버 관리 — 1인 1보드 자동 생성. 공유·권한 없음 (차트·스파크라인도 없음 — Δ+이력 목록)

06성공 판정

  • 계정 2개로 각자 로그인 → 서로의 보드가 안 보인다 (RLS 실측 — 쿼리를 직접 날려도 빈 배열)
  • 같은 상품 재드랍 → 관측이 쌓이고 Δ가 실데이터로 계산된다
  • 통합 주 지정 기능 충족: 테이블 3개(workspaces·products·price_checks) + JOIN 1회(제품⟕관측 임베드) + RLS 정책(owner reads, 쓰기 정책 0 = 쓰기는 service key만)

07내 옵션 + 이유

통합 주의 지정 기능(테이블 3·JOIN·RLS)을 검증된 S04 수집기 위에 세웠다. 격리를 앱 코드가 아니라 DB가 강제하는 게 핵심 — S03에서 문서형(Firestore 보안 규칙)으로 한 것과 정확히 짝이 되는 관계형 답이라 시즌 비교표 소재다. 가격 이력은 append-only 관측 로그로 — 스냅샷 갱신과 달리 시간축의 원본이 남고, S09 크론 주에 그대로 이어 쓴다.

08리스크 + 검증법

걱정되는 것: ① Auth+RLS 조합이 정적 페이지+서버리스에서 실제로 성립하나 ② RLS가 켜지면 수집 함수(service key)와 폴링이 각각 어떻게 갈리나
스파이크로 확인 (수요일 밤): 계정 2개를 시드해 진짜 JWT로 6종 판정 전부 통과 — 격리·JOIN 스코프·비로그인 빈손·로그인 유저 쓰기 403. 상세 05/SPIKE.md. 후퇴 경로(brands 정규화 + 공용 보드)는 쓸 일 없었다.
