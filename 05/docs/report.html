한 줄 결론

사용자마다 데이터가 갈려야 하는 도구라면 격리를 앱 코드가 아니라 Postgres RLS에 맡기겠다 — 정책 세 줄로 교차 조회·비로그인·JOIN 임베드가 전부 DB에서 막혔고(6종 실측), 쓰기 정책을 아예 두지 않아 브라우저는 읽기만, 쓰기는 service key 함수만 하는 경계가 스키마에 박힌다. S03의 Firestore 규칙과 비교하면: 문서형은 경로 설계로 1인 1표를 풀었고 관계형은 unique(owner) 한 줄 + RLS로 1인 1보드를 푼다 — 같은 문제를 스키마가 푸는 방향이 반대다. 다만 여러 주차가 Supabase 프로젝트 하나를 공유하는 구조라면 Auth 설정(Site URL·이메일 도메인 트리거)이 공용 자원이 돼 서로를 밟는다 — 그런 경우엔 주차별 프로젝트를 따로 쓰겠다.
